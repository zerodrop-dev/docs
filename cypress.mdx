# Cypress

ZeroDrop works with Cypress for end-to-end email testing. No Docker, no SMTP server, no mocking.

## Installation

```bash
npm install --save-dev zerodrop-client cypress
```

## Setup

Cypress runs your spec files in the browser. There, ZeroDrop's client can't read `ZERODROP_API_KEY`, and the browser blocks requests to the ZeroDrop API because it's on another origin. So run the client in Cypress's Node process and call it from your specs with `cy.task`:

```javascript
// cypress.config.js
const { defineConfig } = require('cypress');
const { ZeroDrop } = require('zerodrop-client');

// Runs in Node, where it reads ZERODROP_API_KEY
const mail = new ZeroDrop();

module.exports = defineConfig({
  e2e: {
    baseUrl: 'http://localhost:3000',
    setupNodeEvents(on) {
      on('task', {
        newInbox: () => mail.generateInbox(),
        waitForEmail: ({ inbox, timeout = 30000 }) =>
          mail.waitForLatest(inbox, { timeout }),
      });
    },
  },
});
```

If no email arrives in time, or ZeroDrop held the email, `cy.task('waitForEmail')` fails the test with the client's error message.

## Email verification

```javascript
// cypress/e2e/auth.cy.js
describe('Email verification', () => {
  it('user can sign up and verify email', () => {
    cy.task('newInbox').then((inbox) => {
      cy.visit('/signup');
      cy.get('[data-testid="email"]').type(inbox);
      cy.get('[data-testid="submit"]').click();

      cy.task('waitForEmail', { inbox }).then((email) => {
        expect(email.otp).to.not.be.null;

        // Enter OTP
        cy.get('[data-testid="otp"]').type(email.otp);
        cy.get('[data-testid="verify"]').click();
        cy.url().should('include', '/dashboard');
      });
    });
  });
});
```

## OTP verification

```javascript
it('OTP login', () => {
  cy.task('newInbox').then((inbox) => {
    cy.visit('/login');
    cy.get('[data-testid="email"]').type(inbox);
    cy.get('[data-testid="submit"]').click();

    cy.task('waitForEmail', { inbox }).then((email) => {
      // OTP auto-extracted — no regex needed
      cy.get('[data-testid="otp"]').type(email.otp);
      cy.get('[data-testid="verify"]').click();
    });
  });
});
```

## Magic link verification

```javascript
it('magic link verification', () => {
  cy.task('newInbox').then((inbox) => {
    cy.visit('/signup');
    cy.get('[data-testid="email"]').type(inbox);
    cy.get('[data-testid="submit"]').click();

    cy.task('waitForEmail', { inbox }).then((email) => {
      // Navigate to verification link
      cy.visit(email.magicLink);
      cy.url().should('include', '/dashboard');
    });
  });
});
```

## In GitHub Actions

Without an API key, one sender can reach only 5 different inboxes a day, and each test above uses its own inbox. Get a free key at [zerodrop.dev/keys](https://zerodrop.dev/keys), save it as the repository secret `ZERODROP_API_KEY`, and pass it to the step that runs Cypress:

```yaml
- name: Run Cypress tests
  run: npx cypress run
  env:
    ZERODROP_API_KEY: ${{ secrets.ZERODROP_API_KEY }}
    CYPRESS_BASE_URL: ${{ secrets.STAGING_URL }}
```

The `newInbox` task makes a fresh inbox for each test, so you don't need the setup-zerodrop action here. Inbox names then start with your key's prefix, and only your key can read them.
