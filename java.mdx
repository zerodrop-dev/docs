## Install

**Gradle:**

```groovy
repositories {
    maven { url 'https://jitpack.io' }
}

dependencies {
    testImplementation 'com.github.zerodrop-dev:zerodrop-java:v0.3.0'
}
```

**Maven:**

```xml
<repositories>
    <repository>
        <id>jitpack.io</id>
        <url>https://jitpack.io</url>
    </repository>
</repositories>

<dependency>
    <groupId>com.github.zerodrop-dev</groupId>
    <artifactId>zerodrop-java</artifactId>
    <version>v0.3.0</version>
    <scope>test</scope>
</dependency>
```

Java 11+ · one dependency (Gson).

## Quick start

```java
import dev.zerodrop.ZeroDrop;
import dev.zerodrop.Email;
import java.time.Duration;

ZeroDrop mail = ZeroDrop.create();
String inbox = mail.generateInbox();
// => "swift-x7k29ab@zerodrop-sandbox.online"

// Trigger your app's email flow with the inbox address...

Email email = mail.waitForLatest(inbox, Duration.ofSeconds(15));

email.otp();       // Optional["123456"] — auto-extracted, no regex
email.magicLink(); // Optional["https://..."] — auto-extracted
```

## JUnit 5 + Selenium

```java
@Test
void emailVerificationWithOtp() {
    ZeroDrop mail = ZeroDrop.create();
    String inbox = mail.generateInbox();

    driver.get("https://yourapp.com/signup");
    driver.findElement(By.name("email")).sendKeys(inbox);
    driver.findElement(By.name("password")).sendKeys("TestPassword123!");
    driver.findElement(By.cssSelector("button[type=submit]")).click();

    Email email = mail.waitForLatest(inbox, Duration.ofSeconds(15));

    String otp = email.otp().orElseThrow();
    driver.findElement(By.name("otp")).sendKeys(otp);
    driver.findElement(By.cssSelector("button[type=submit]")).click();

    assertTrue(driver.getCurrentUrl().endsWith("/dashboard"));
}
```

## Filtering

```java
import dev.zerodrop.Filter;

Filter filter = Filter.builder()
    .from("noreply@yourapp.com")
    .hasOtp(true)
    .build();

Email email = mail.waitForLatest(inbox, Duration.ofSeconds(15), filter);
```

All string filters are case-insensitive partial matches.

## Parallel tests

`generateInbox()` runs locally — safe with JUnit parallel execution and TestNG parallel suites. Every call returns a unique isolated inbox.

## Free API key (private inboxes)

Without a key, anyone who knows an inbox's name can read it, and one sender can reach only 5 different inboxes a day: past that, the inbox gets a notice from `notice@zerodrop.dev` instead of the email. Sign in with GitHub at [zerodrop.dev/keys](https://zerodrop.dev/keys) for a free key and set it as `ZERODROP_API_KEY`. With v0.2.0 or later, the client reads it, `generateInbox()` starts names with your key's prefix, only your key can read those inboxes, and the 5-inbox limit doesn't apply to them (your account can receive up to 300 emails a day):

```java
ZeroDrop mail = ZeroDrop.create(); // reads ZERODROP_API_KEY
mail.generateInbox();
// "k7x2-swift-x7k29ab@zerodrop-sandbox.online", where k7x2 is your prefix
mail.prefix(); // Optional[k7x2]
```

## Error handling

```java
try {
    Email email = mail.waitForLatest(inbox, Duration.ofSeconds(15));
} catch (ZeroDropException.Timeout e) {
    // No email arrived
} catch (ZeroDropException.Auth e) {
    // The inbox belongs to another key's prefix, or your key is wrong; e.getMessage() says which
} catch (ZeroDropException.Held e) {
    // No API key, and ZeroDrop held the email (daily limit); e.getMessage() says why
} catch (ZeroDropException.Network e) {
    // Transport failure
}
```

`ZeroDropException.Held` is new in v0.3.0. Without an API key, one sender can reach only 5 different inboxes a day; past that, the email isn't stored and the inbox gets a notice instead. `waitForLatest` then throws `ZeroDropException.Held` at once rather than waiting for the timeout, and `fetchLatest` throws it when nothing matches. Older versions treat the notice as an email: without a filter they return it, and an OTP filter skips it, so the wait times out. A free key from [zerodrop.dev/keys](https://zerodrop.dev/keys) lifts the limit for inboxes under your key's prefix.

## Workspaces & self-hosting

A Workspace receives mail on a domain of its own, such as `yourcompany-qa.com`, and every inbox on it can be read only with your key. Set the domain as `ZERODROP_DOMAIN`, which `ZeroDrop.create()` reads like your key, or pass it to the builder (v0.4.0 or later):

```java
ZeroDrop mail = ZeroDrop.builder()
    .apiKey(System.getenv("ZERODROP_API_KEY"))
    .domain("yourcompany-qa.com")
    .build();
String inbox = mail.generateInbox();
// "k7x2-swift-x7k29ab@yourcompany-qa.com"
Email email = mail.waitForLatest(inbox, Duration.ofSeconds(15));
```

Any address on the domain works, including one you name yourself: `mail.waitForLatest("qa@yourcompany-qa.com")` reads the inbox `k7x2-qa`. `mail.domain()` returns the domain in use, and a value that isn't a domain name makes `ZeroDrop.create()` and `build()` throw `IllegalArgumentException`. Use the domain as your API keys page shows it. See [Workspaces](/workspaces) for how mail on it is filed.

A self-hosted instance takes its own base URL:

```java
ZeroDrop mail = ZeroDrop.builder()
    .apiKey(System.getenv("ZERODROP_API_KEY")) // optional since v0.2.0: the client reads it anyway
    .baseUrl("https://your-instance.yourdomain.com")
    .build();
```
